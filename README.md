# AGR Adaptive Texture Optimizer 26

Рабочая версия 26: C++20, Qt 6/QML и libdeflate. В программе оставлен один
основной режим **AGR Adaptive RGB24**. Он подбирает максимально богатое
RGB24-представление, которое укладывается в выбранный пользователем предел.

В интерфейс входят синхронный zoom/pan, сравнение двух кадров и режим «Шторка»,
динамический цветовой акцент, космический фон с режимами FX MAX/FX ECO,
орбитальная камера и интерактивная звезда.

## Сборка Windows

### Автоматически — готовый portable EXE

Проект содержит workflow `.github/workflows/windows-portable.yml`. После
загрузки проекта в GitHub откройте **Actions → Build Windows Portable EXE → Run
workflow**. В результате появится artifact
`AdaptiveTextureOptimizer-26-Windows-Portable`. Его нужно скачать, распаковать
и запустить `AdaptiveTextureOptimizer.exe`. Python, Qt и Visual Studio на
компьютере пользователя не нужны: необходимые Qt DLL и MSVC runtime уже лежат
рядом с EXE.

### Локально

Установите Visual Studio 2022 (Desktop development with C++), CMake, Git и Qt
6.6+ с комплектом MSVC. Затем откройте `x64 Native Tools Command Prompt`:

```bat
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=C:/Qt/6.8.3/msvc2022_64 -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
C:/Qt/6.8.3/msvc2022_64/bin/windeployqt --qmldir qml build/AdaptiveTextureOptimizer.exe
```

Путь и версию Qt замените на установленные у вас. CMake самостоятельно загрузит
закреплённую версию libdeflate. Готовый EXE принимает PNG перетаскиванием на окно
или на сам файл программы.

## Один режим AGR Adaptive RGB24

Старая лаборатория из десяти режимов больше не используется. Версия 26 запускает
один предсказуемый конвейер: сначала пробует lossless RGB24, затем адаптивно
уменьшает число цветовых представителей и уточняет результат бинарным поиском.
Для сложных изображений предусмотрены уровни вплоть до одного представителя,
поэтому допустимый предел размера не подменяется фиксированными 3 MB.

Палитра существует только внутри оптимизатора. Перед PNG-кодированием изображение
всегда разворачивается обратно в `RGB888`; финальная проверка требует PNG color
type 2 и bit depth 8, то есть настоящий RGB24. Алгоритм увеличивает число
представителей бинарным поиском, пока следующий вариант уже не помещается в
заданный размер. Это тратит доступный бюджет качественно, без возврата случайных
исходных пикселей и цветных выбросов.

## Текущий конвейер

1. Декодирование в RGB24; 8K уменьшается напрямую до 2K.
2. Lossless-поиск фильтров None/Sub/Up/Paeth/adaptive MinSum.
3. Упаковка libdeflate уровня 10.
4. Если выбранный предел не достигнут — AGR Adaptive RGB24 ищет максимально богатое
   представление, которое реально проходит лимит.
5. После каждого кандидата измеряются размер, PSNR, mean ΔRGB и max ΔRGB.
6. Финальный PNG декодируется и сверяется с выбранным RGB-массивом.

## Автоматическая проверка

GitHub Actions собирает portable-комплект, трижды проверяет запуск QML-интерфейса
и отдельно выполняет сквозной self-test оптимизации: создаёт тестовый PNG,
обрабатывает его, проверяет предел размера, RGB24 и точное декодирование результата.
